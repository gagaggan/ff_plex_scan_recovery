# Plex Scan Recovery

Plex Mate 변경 스캔 기록과 Plex DB를 대조해 누락된 파일만 복구하는 FlaskFarm 플러그인.

전체 주기 스캔을 대체하며 Plex Mate의 기존 ADD 큐를 사용합니다. 개발은 기능 단위 PR로 진행합니다.

## 설치 및 사용

FF 플러그인 설치에 `https://github.com/gagaggan/ff_plex_scan_recovery`를 입력합니다. Plex Mate가 먼저 설치되어 있어야 합니다.

1. 설정 화면에서 Plex 연결 확인.
2. 스케줄 화면에서 대상 섹션 ID·이름을 선택하고 저장. 미선택은 모든 섹션.
3. 검토만 실행으로 대상과 기록 확인.
4. 자동 복구 켜기로 예약 등록. 기본 5분마다, 최초 설치는 자동 복구 OFF.
5. 상태 화면에서 파일별 결과·최근 단계·전체 진행률 확인 (100개/페이지).

## 동작과 부하

- 최근 30일 Plex Mate 변경 이력을 한 번에 200개 읽고 Plex DB는 최대 100개 파일의 정확한 경로·섹션을 대조합니다.
- 큐에 추가하는 복구 작업은 한 번에 하나입니다. 기존 스캔 작업이 있으면 대기합니다.
- Plex Mate의 완료 상태만 믿지 않고 실제 파일의 DB 등록 여부를 확인합니다.
- 원격 파일 존재 확인은 제출할 파일에 대해서만 합니다. 원본 없는 파일·삭제 요청·NFO·이미지는 제외합니다.
- 재시도는 기본 60분 간격, 최대 3회. 상태는 플러그인 자체 SQLite에 보존합니다.
- Plex의 재생·일시정지·버퍼링 세션이 있으면 사전검토·새 큐 등록을 대기합니다. 이미 등록된 작업은 강제로 중단하지 않습니다.
- 최대 검토 횟수 이후에는 다음 예약에서 이어갑니다. 이는 전체 대상 개수 제한이 아닙니다.
- 폴더 검토는 지정한 하위 폴더의 파일명만 읽습니다. 최대 2,000개 항목이며 재귀 순회하지 않습니다.

## 제한

변경 이력에 없거나 Plex Mate에서 이미 삭제한 기록은 자동 발견할 수 없습니다. 이 경우 상태 화면의 폴더 검토로 대상을 추가하세요. 사전검토는 현재 Plex DB 등록 여부를 확인하는 기능이며 파일 손상·메타데이터 품질 검사는 아닙니다.

큐 등록 중 응답 유실처럼 제출 여부가 불확실하면 재요청하지 않고 `큐 등록 확인 필요`로 보류합니다. Plex Mate 기록의 callback_id와 대조해야 합니다. 진행률은 현재 발견된 대상 기준이므로 이력 검토 중 총수가 증가할 수 있습니다.

## 샤이니 함께 검토

기본값은 Plex Mate의 `scan_shyni_use` 설정을 따릅니다. 샤이니 URL·API 토큰·경로 변환도 기존 설정을 사용합니다. 샤이니 섹션 ID는 Plex ID를 재사용하지 않고 경로로 자동 조회합니다.

샤이니는 `/compat/parts`의 정확한 파일 경로·섹션·`available` 상태로 등록을 확인합니다. 폴더나 작품 메타데이터가 있다는 이유만으로 파일이 등록됐다고 판단하지 않습니다. 샤이니 함께 검토 시 파일 5개씩만 대조합니다.

Plex만 누락되면 Plex Mate 큐, 샤이니만 누락되면 샤이니의 파일 부분 스캔 API를 호출합니다. 둘 다 누락되면 Plex 완료 후 샤이니를 처리합니다. 복구 요청에 한해서만 Plex Mate 자동 샤이니 분기를 건너뛰어 중복 요청을 막습니다. 기존 GDS/Plex Mate 스캔 설정은 바꾸지 않습니다.

샤이니 요청은 Idempotency-Key로 재시작·응답 유실에도 같은 작업을 사용합니다. 작업 종료 후 실제 파일 등록을 다시 확인하고 목적지별 결과를 별도로 표시합니다. 샤이니에 해당 라이브러리가 없으면 `섹션 없음`으로 표시하며 요청하지 않습니다.

샤이니 자체 재생 세션 조회에는 API 키와 별도의 관리자 세션 토큰이 필요합니다. 선택 설정을 입력하면 샤이니 재생도 대기 기준에 포함하며 조회 실패 시 요청을 보류합니다. 미입력 시 재생 보호는 Plex 세션에만 적용합니다. 검토 범위는 Plex 라이브러리에 속한 파일이며 샤이니에만 있는 라이브러리는 현재 자동 발견 대상이 아닙니다.
